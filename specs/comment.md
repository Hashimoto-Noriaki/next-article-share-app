# コメント機能 E2Eテスト計画

## Application Overview

テックブログ共有アプリの記事詳細ページ（/articles/[id]）にあるコメント機能を対象としたE2Eテスト計画。コメント欄は `<section>` 内に「コメント (N)」の見出し、投稿フォーム（プレースホルダー「コメントを入力...」のテキストエリアと「コメントする」ボタン）、コメント一覧が並ぶ。0件のときは「コメントはまだありません」と表示される。自分のコメントには「編集」「削除」ボタンが表示され、他人のコメントには表示されない。記事の投稿・編集・削除、認証自体は対象外とし、コメントの投稿・編集・削除と、編集・削除ボタンの出し分けのみを検証する。UI構成と挙動は実ブラウザ（localhost:3000）で探索して確認済み。

各シナリオはseedのログイン状態を引き継がず、createTestUser()/signup()で自分でログイン状態を作る。2人目のユーザーが必要な1.4は、投稿者を `browser.newContext()` で作った別コンテキストで動かし、閲覧者はテストの `page` で操作する。ログアウトは使わない（ログアウト直後にセッションが復活する不具合 #485 があるため）。

## 探索で確認した実挙動と推奨ロケーター

- ユーザー名は createTestUser() のデフォルトだとどちらも「テストユーザー」になる。投稿者と閲覧者を区別したい場合は createTestUser('投稿者')、createTestUser('閲覧者') のように名前を渡す。
- 見出し: `page.getByRole('heading', { name: 'コメント (1)' })`（半角スペース1つ、件数は半角数字）。
- 投稿フォーム: `page.getByPlaceholder('コメントを入力...')` と `page.getByRole('button', { name: 'コメントする' })`。投稿成功後、入力欄は空に戻り、ページを再読み込みせずに一覧と見出しの件数が更新される。
- コメント本文は `<p>` に入り、投稿者名と日付（`テストユーザー2026/9/29` のように連結して表示）、「編集」「削除」ボタンと同じ親の `<div>`（コメント要素）の中に並ぶ。コメント要素にはrole・data-testidがない。
- 推奨ロケーター（複数コメントがあるとき）: `page.getByText(本文, { exact: true }).locator('..')` でコメント要素を取得し、その中で `getByRole('button', { name: '編集' })` / `getByRole('button', { name: '削除' })` を探す。
- 推奨ロケーター（コメントが1件のとき）: `page.locator('section')` にスコープする。記事本体の「削除」ボタンは `<article>` 内にあり `<section>` の外なので、`page.locator('section').getByRole('button', { name: '削除' })` でコメントの削除ボタンだけを特定できる。
- 注意: 記事著者が見るページでは、記事本体にも「編集」（リンク）と「削除」（ボタン）がある。`page.getByRole('button', { name: '削除' })` をそのまま使うとコメントの削除ボタンと記事の削除ボタンが両方ヒットするので、必ずコメント要素または `<section>` にスコープする。「編集」は記事側が `link` なので、`getByRole('button', { name: '編集' })` ならコメント側のみにヒットする。
- 編集モードになると本文の `<p>` は消え、代わりにテキストエリア（アクセシブル名「コメント」）と「更新」「キャンセル」が表示される。本文の getByText は編集中には使えない。編集中の操作は `page.getByRole('textbox', { name: 'コメント', exact: true })` で行う（exact を付けないと投稿フォームの「コメントを入力...」にもヒットして strict mode 違反になる）。
- 削除: 「削除」クリックでブラウザ標準の window.confirm ダイアログ（type=confirm）が表示される。メッセージは「コメントを削除しますか？」で、独自モーダルではない。キャンセル（dismiss）するとコメントは残り件数も変わらない。OK（accept）するとコメントが消え、見出しが「コメント (0)」になり「コメントはまだありません」が表示される。ダイアログはボタンをクリックする前に `page.once('dialog', ...)` で待ち受ける。
- 編集: 「編集」クリックでテキストエリアに元の本文が入った状態で表示される。「更新」で本文が更新されて編集フォームが閉じる（ダイアログは出ない）。「キャンセル」で編集フォームが閉じ、書き換え途中の内容は破棄され元の本文が表示される。再度「編集」を開いたときも元の本文が入っている。
- 他人のコメント: 本文・投稿者名・日付は表示されるが、「編集」「削除」ボタンは存在しない。投稿フォームはログイン中なら表示される。

## Test Scenarios

すべてのシナリオを `e2e/comment.spec.ts` にまとめる。

## Test Scena

### 1. コメント機能

**Seed:** `e2e/seed.spec.ts`

#### 1.1. コメントを投稿する

**File:** `e2e/comment.spec.ts`

**Steps:**

1. createTestUser() でユーザーを作成し、signup() で新規登録・ログインする
2. createTestArticle() でテスト記事データを作成し、createArticle() で記事を公開する
3. navigateToArticle() で記事詳細ページへ遷移する
4. 見出し「コメント (0)」と「コメントはまだありません」が表示されていることを確認する
5. ユニークなコメント本文（例: `コメント ${Date.now()}`）を用意し、プレースホルダー「コメントを入力...」のテキストエリアに入力する
6. 「コメントする」ボタンをクリックする

**Expected Results:**

- 投稿したコメント本文がコメント欄に表示される
- 見出しが「コメント (1)」になり、「コメントはまだありません」は表示されなくなる
- コメント要素内に投稿者名（signup したユーザー名）が表示される
- 投稿フォームのテキストエリアが空に戻る（toHaveValue('')）
- 投稿した自分のコメントに「編集」「削除」ボタンが表示される（コメント要素または section にスコープして確認する）

#### 1.2. 自分のコメントを編集する

**File:** `e2e/comment.spec.ts`

**Steps:**

1. createTestUser() + signup() でログインし、createTestArticle() + createArticle() で記事を公開、navigateToArticle() で詳細ページへ遷移する
2. ユニークな本文A（`元コメント ${Date.now()}`）を投稿し、表示されるまで待つ
3. 本文Aのコメント要素内の「編集」ボタンをクリックする
4. アクセシブル名「コメント」（exact）のテキストエリアが表示され、本文Aが入っていること、「更新」「キャンセル」ボタンが表示されていることを確認する
5. テキストエリアをユニークな本文C（`キャンセル用 ${Date.now()}`）に書き換え、「キャンセル」ボタンをクリックする
6. 本文Aがそのまま表示されていることを確認する
7. 再度「編集」ボタンをクリックし、テキストエリアの値が本文Aに戻っていることを確認する
8. テキストエリアをユニークな本文B（`編集後コメント ${Date.now()}`）に書き換え、「更新」ボタンをクリックする（「更新」は処理中のみ disabled になるため、クリックは1回だけにする）

**Expected Results:**

- キャンセル後は編集フォームが閉じ、本文Aが表示され、本文Cは表示されない
- 更新後、本文Bが表示され、本文Aは表示されない
- 更新後は編集フォーム（「更新」「キャンセル」ボタン）が閉じ、「編集」「削除」ボタンが再表示される
- コメント件数は「コメント (1)」のまま
- 編集中・更新時にダイアログは表示されない

#### 1.3. 自分のコメントを削除する（確認ダイアログあり）

**File:** `e2e/comment.spec.ts`

**Steps:**

1. createTestUser() + signup() でログインし、createTestArticle() + createArticle() で記事を公開、navigateToArticle() で詳細ページへ遷移する
2. ユニークなコメント本文を投稿し、表示されるまで待つ
3. page.once('dialog', ...) で、ダイアログの type と message を記録して dismiss() するハンドラを登録する（ボタンをクリックする前に登録する）
4. `page.locator('section')` 内の「削除」ボタンをクリックする（記事本体の「削除」ボタンと区別するため section にスコープする）
5. コメント本文が残っており、見出しが「コメント (1)」のままであることを確認する
6. 再度 page.once('dialog', ...) で accept() するハンドラを登録し、同じ「削除」ボタンをクリックする

**Expected Results:**

- 「削除」クリックでブラウザ標準の window.confirm ダイアログ（type は confirm）が表示され、メッセージは「コメントを削除しますか？」である（独自モーダルではない）
- ダイアログをキャンセルするとコメントは削除されず、本文も件数も変わらない
- ダイアログを OK すると本文が消え、見出しが「コメント (0)」になり、「コメントはまだありません」が表示される

#### 1.4. 他人のコメントには編集・削除ボタンが表示されない

**File:** `e2e/comment.spec.ts`

**Steps:**

1. browser.newContext() で投稿者用のコンテキストとページを作る（logout() は使わない）
2. 投稿者用ページで、createTestUser('投稿者') でユーザーを作成し、signup() で新規登録・ログインする
3. 投稿者用ページで、createTestArticle() + createArticle() で記事を公開する
4. 投稿者用ページで navigateToArticle() し、ユニークなコメント本文（`投稿者のコメント ${Date.now()}`）を投稿して表示されるまで待つ
5. 投稿者用ページで、そのコメント要素内に「編集」「削除」ボタンが表示されていることを確認する
6. 投稿者用のコンテキストを閉じる
7. テストの page で、createTestUser('閲覧者') を作成し、signup() で新規登録・ログインする
8. navigateToArticle() で同じ記事の詳細ページへ遷移する
9. 手順4のコメント本文が表示されていることを確認する
10. `page.getByText(本文, { exact: true }).locator('..')` で取得したコメント要素内に、「編集」「削除」ボタンがあるか確認する
11. 閲覧者が自分のコメント（ユニークな本文）を投稿し、そのコメント要素には「編集」「削除」が表示され、投稿者のコメント要素には引き続き表示されないことを確認する

**Expected Results:**

- 投稿者のコメント本文と投稿者名（投稿者）が閲覧者のページに表示される
- 投稿者のコメント要素内に「編集」ボタン・「削除」ボタンが存在しない（toHaveCount(0)）
- 閲覧者自身のコメント要素にのみ「編集」「削除」ボタンが表示される
- 見出しは「コメント (2)」になる
- 記事の著者ではない閲覧者のページには、記事本体の「編集」「削除」も表示されない（確認するなら記事側のロケーターは section の外に限定する）
